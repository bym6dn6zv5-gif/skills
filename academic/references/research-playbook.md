# 学术研究操作法

## 从问题形成最小研究单元

把议题改写成一句可检验的问题：在什么对象和条件下，相比什么已有方法，某个机制或方法会使什么指标怎样变化？

区分用户是在探索方向、验证设想、复现论文还是撰写结果。优先完成当前阶段，不自动把一次论文阅读扩展为整套投稿工程。

需要推荐选题时，先筛基础、计算资源、数据可得性与验证成本。默认给一个最值得先验证的题目及理由；列出能以最小代价否定它的实验。把“有潜力”与“已证实创新”分开。

## 阅读与核验文献

1. 先读取用户提供的文件、链接或明确相关材料，确认标题、作者、年份与版本。
2. 根据关键未知制定检索词；需要时结合中英文术语、方法名、基准和反向证据。
3. 优先读原始研究与官方数据；将综述用作导航，用原论文核对关键技术结论。
4. 只摘要实际获得的内容；只有摘要时明确评估范围，不补造公式、实验设置和附录。
5. 遇到结论冲突时比较假设、样本、指标、实验条件与版本，不用引用数量投票决定。
6. 关键证据足以回答本次问题时停止扩散；不能据有限搜索断言“首次提出”“无人研究”。

深入读一篇论文时，按需整理以下信息，不为短问题强制输出整张表：

| 项目 | 需要回答的问题 |
| --- | --- |
| 研究问题 | 具体解决什么困难，现有方法为何不足？ |
| 假设与对象 | 模型、数据、适用条件和排除条件是什么？ |
| 方法 | 核心机制是什么，关键公式或算法如何成立？ |
| 证据 | 哪些实验、比较和统计支持了哪些主张？ |
| 局限 | 什么尚未证明，什么条件下可能失效？ |
| 可复现性 | 数据、代码、参数与资源是否足够，缺口是什么？ |

## 从阅读走向独立判断

- 对主要结论问：改变哪一假设会使它不成立？是否有更简单的解释？能否构造反例？
- 解释复杂方法时先画清输入、状态、约束与输出，再展开关键公式；不要用术语密度替代解释。
- 对跨学科迁移，指出结构上真正对应的部分及不对应的部分，并提出可检验预测。
- 判断创新时逐项比较最接近工作的问题、假设、方法与证据；把更换数据、调参和术语重命名与实质贡献区分开。
- 没有足够近邻文献证据时给“暂定差异点”和待查项，不给新颖性保证。

## 设计实验与复现

需要验证方法时优先交付最小可运行方案，再根据结果扩大规模。明确：

1. **假设**：什么观测支持它，什么观测会否定它。
2. **比较**：简单基线、领域常用基线与待验证方法，公平对齐信息与调参预算。
3. **条件**：数据来源、样本或场景选择、训练验证测试划分；适用时防止数据泄漏。
4. **指标**：主指标、约束指标、失败情形及选择原因。
5. **归因**：用消融区分哪个组件产生效果，检查负结果与替代解释。
6. **稳定性**：在适用时记录随机种子、重复次数、变化范围与不确定性；不要机械要求每种确定性计算都重复多次。
7. **复现**：记录版本、参数、资源、命令和原始输出；将示意代码与实际运行结果分开。

例如，车辆路径跟踪选题可从固定路径和速度下的控制基线开始，再测试曲率、速度或模型误差变化。按研究问题选择横向误差、控制平滑性、约束违反与计算耗时等指标；不要仅凭一个平均误差改善就宣称全面优越。

没有条件运行时，给代码或实验说明及预期检查点，清楚标明尚未执行。用户只要求方案时，不以执行完全部实验作为交付前提。

## 写作与论证

- 先建立“主张 → 证据 → 适用条件 → 剩余未知”的对应，再写正文。
- 可以协助写摘要、引言、方法、讨论、代码说明和完整稿件；保留用户明确提出的观点与风格要求。
- 无数据时用“［待填：真实实验结果］”等显式占位符，不生成看似真实的表格数字、p 值或引用。
- 引用只使用可核验信息；未核验的条目列为待查，不能靠补齐 DOI 或页码制造可信度。
- 区分“观察到”“推断”“假设”“计划验证”；让语气强度匹配证据。
- 修改学术表达时优先修复概念、论证、具体性与连贯性；不把随机口语化、堆砌错误或检测器分数当作质量目标。

## 校准范围与结束条件

对一般研究协助，交付一个当前判断、最重要的证据或依据、影响判断的缺口以及必要的下一步。复杂任务按用户要求扩展结构，不强制套模板。

当核心问题已答、关键依据已查、材料缺口已如实标明时交付。只有新增证据、实质错误、用户扩大范围或未解决的决定性问题才继续扩大工作。
