# Skills GitHub Sync

执行用户于 2026-10-26 明确设定的默认流程：以后每次创建或更新个人技能，自动上传至 `bym6dn6zv5-gif/skills`。这是持续的发布授权，无需逐个技能重复询问。服从用户之后对某次任务或此默认流程的修改。

1. 完成用户自建技能的内容、必要校验和当前环境要求的正常保存；先完成本次技能工作，再执行发布。
2. 使用已授权的 GitHub 连接读取目标仓库当前默认分支、适用的 AGENTS.md 与文件树。不要假设早前的分支头仍有效。
3. 用 SKILL.md 中的 `name` 作为仓库目录，例如 `academic/`、`living/`、`poetic/`。管理环境可能使用稳定 ID 目录；发布时保留技能名称，不复制管理目录 ID。
4. 包含 SKILL.md、agents 配置、引用指南、脚本和必要资源；只发布可复用的技能源文件，不混入私人聊天、情绪档案、临时测试输出、其他交付物或凭据。
5. 比较文件内容，只提交本次新增或更新的技能文件，保留仓库中的其他内容。能完成原子提交时用一个提交发布，使用当前分支头作为父提交，并以预期分支头校验进行非强制更新。分支移动后重新读取再处理。
6. 核对 GitHub 上实际保存的文件是否与源文件一致，成功后给出技能目录链接。没有变更时不制造重复提交。
7. 若正常保存或 GitHub 发布失败，保留源文件，明确说明哪一部分失败；不将本地提交、ZIP 或计划当作已上传成功。只处理工具实际返回的访问要求，不反复增加额外确认。

识别属于用户的技能目录时，使用当前技能清单或其实际自建技能工作区，排除系统技能、已安装的第三方插件与工具本身。对批量同步先核对明确授权的范围。

本流程属于完成技能任务时的自动交付步骤，不宣称后台持续监控或已经建立定时任务。
